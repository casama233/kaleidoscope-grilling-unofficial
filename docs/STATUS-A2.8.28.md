# A2.8.28 — cooking audio and truthful shared-guide onboarding

Lit grills with food now play the original cooking ambience; empty, extinguished, destroyed or unloaded grills stop their own native sound instance. Insertion, flipping, brushing, seasoning, extraction, skewer disassembly, bottle placement/stacking and completed seasoning use the corresponding Java audio. Successful transaction feedback follows commit, so rejected operations do not announce success. Interrupted seasoning and eating stop only the associated use sound; native chewing is no longer triggered again by each scripted bite.

All 17 OGG files and 13 original sound events come from the checksum-verified Java 1.1.1 release, including the six previously missing files. Existing eating aliases are retained. `development/gameplay_core/fixtures/released-audio-1.1.1.json` records each original asset hash. The grill track is renewed every 569 ticks without overlapping instances; per-block sound handles avoid globally stopping nearby grills.

The Cookery guide catalog advances to 0.3.6 and references the verified unmodified author Cookery 1.0.8 guide. It keeps the shared entry point, six cooking root categories and one combined page per item, following [GUIDE-STANDARD.md](GUIDE-STANDARD.md). The first-skewer route uses obtainable fish and explicitly teaches crafting/equipping the empty starter, block interaction, four flips, seasoning cost, the 1.25-second eating checkpoint and the four-paper blank recipe book. Beef/chicken acquisition blockers appear first on affected pages. Heat lore uses a client translation key and preserves foreign RawMessage lore.

The public host localizes its known cooking methods when given canonical method IDs; Crafting now maps to its recognized Crafting Table identifier. Method labels unknown to host API v1 still use canonical English IDs. Host-owned ingredient names remain subject to the original host's lookup priority. Dragon powder's current Bedrock amplifier limits are disclosed rather than presented as Java parity.

Source regressions and isolated BDS evidence are separate from client acceptance. Audio loudness, touch controls, the visible guide layout and eating sound overlap still require real clients. This release does not finish visible grill contents, bottle fluid layers, plate arrangements, Java-accurate hand animations, survival acquisition blockers or full saved-world migration. Production deployment requires the full family receipt and all required acceptance evidence.
