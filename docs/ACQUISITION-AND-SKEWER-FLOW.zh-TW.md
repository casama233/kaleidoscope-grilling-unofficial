# 牛肉塊、雞皮取得與烤串流程研討

2026-10-02；Grilling canonical runtime 2.8.28，作者 Cookery 1.0.8，Java Grilling 1.1.1。

**目前不能宣稱所有烤串的完整生存流程跑通。牛肉塊、雞皮卡在取得端；提供食材後，19 種固定烤串與一種秘製串的來源程式連續測試通過。** 普通烤串是另外一個可穿製、不可放入生串烤製管線的配置，不能把它算成第 20 種固定熟串。

本輪新增測試、原包重現程式與方案文件，沒有變更輸出 runtime，版本及輸出 hash 保持 2.8.28。沒有改 Luosen 正式包、原作者包、BSM 全檔替換、家族鎖或准入政策。

## 取得端的確切原因

| 材料 | Java 規則 | 作者 Bedrock 1.0.8 實際選擇 | 缺口 |
| --- | --- | --- | --- |
| 牛肉塊 | 一份生牛肉，4 次切割，完成時輸出牛肉塊 ×2；替換原牛雜砧板配方 | 內建 `minecraft:beef` 配方優先，輸出小塊生牛雜 ×2 | 公開擴充配方雖回覆註冊成功，仍不能取代內建結果 |
| 雞皮 | 切雞成功出料時保留宿主主產物，另加雞皮 1～3 片；均勻隨機 | 生雞切割後只有小塊生肉 ×2 | 沒有受支援的切雞副產物欄位或可靠完成收據 |

原包會先選 `BOARD_RECIPES[input]`，才選公開擴充配方。牛肉註冊成功只代表擴充表收到了資料，不能等同實際選中。加入 `priority`、`override` 也無效：1.0.8 的正規化會刪去這些未支援欄位。雞皮的 `bonusOutputs` 同樣被刪去。

現有砧板操作需要 **4 次切割，再一次持刀互動釋放結果**；第 4 次切割後不會立即出料。正常路徑扣一份食材、扣 4 點刀具耐久。這個操作節點是重現與真人驗收必須注意的部分。

不能靠「看見私人砧板資料清空」來補發雞皮。原包出料函式可吞掉生成失敗，接著仍清空砧板；在儲存替身的失敗注入中，確實出現「砧板清空、主產物零份」。此時補發雞皮會把失敗當成功，並可能在取消、換人或重啟時誤發。這項證據是原函式的來源測試，不是原生故障或真人實測。

使用菜刀擊殺雞的現有煙火掉落是雞翅，不能當成 Java 雞皮取得規則。用剪刀或工作台轉換也不能無標註地冒充 Java 切雞副產物。

另外，現有五個煙火砧板擴充配方已逐項在原作者函式重現：粉製紅薯片、胡蘿蔔丁、土豆片、生饅頭片、碎魚腥草，結果與數量均正確，沒有內建輸入衝突。這仍不證明其上游種植、磨粉與真人操作都已驗收。

## 可行方案與取捨

| 方案 | 牛肉塊 | 雞皮 | 與 Java 一致性 | 判斷 |
| --- | --- | --- | --- | --- |
| 擴充作者公開砧板 API | 明確授權的內建配方取代，仍切 4 次、出 2 塊 | 宿主在完成出料交易中同時提交主產物與隨機 1～3 片雞皮 | 可保留原規則與既有砧板體驗 | **首選；目前 API 尚未提供，不能立即註冊假欄位當修復** |
| 現有公開工具轉換 | 已重現：剪刀一次轉成 2 塊 | 已重現：剪刀一次轉成固定 2 片，但不再出主產物 | 切割步驟、耐久與鸡皮產出都改變 | 可作明確標註的替代玩法，不能當忠實修復 |
| 自有煙火食材處理站 | 自有狀態機保留 4 刀與 2 塊 | 自有交易保留主產物與 1～3 片副產物 | 數量規則可保留，但新增設備與操作入口 | 若需先提供忠實數量的生存取得，可另立功能設計；工作量與導覽負擔較大 |

建議先推動作者 API；把兩個問題保留為明確的取得缺口，直到實際 capability 可協商、原包選擇及出料驗證通過。若要短期可玩，需要明確選擇並標註替代規則；本輪未擅自加入剪刀配方或另一套切雞玩法。

可交付作者的需求與重現步驟在 [公開介面提案](COOKERY-BOARD-API-PROPOSAL.md)。回饋紀錄狀態為 **draft，尚未外送**；本倉庫的 AGENTS.md 禁止向其他倉庫寫入，沒有代發 issue 或訊息。

## 烤串流程核對

```mermaid
flowchart LR
    A[取得食材] --> B[木棍合成空串]
    B --> C[副手空串 主手食材逐項穿串]
    C --> D[點火並放入最多三串]
    D --> E[按串數刷油]
    E --> F[空手翻面四次 每次間隔一秒]
    F --> G[按串數撒完成的調料]
    G --> H[取出熱食 保存調味資料]
    H --> I[食用完成或有效停止節點結算一次]
    X[牛肉塊 雞皮取得缺口] -.-> A
```

來源程式連續測試使用實際 `threadCurrent`、`handleGrill`、`extract`、`hungerSettle` 函式及實際物品資料適配器；只用儲存與事件替身，不建構 Minecraft 模擬玩家。新增 24 項測試：

- 19 種固定熟串逐項從配方食材穿製，確認食材扣除，刷油、四翻、撒料、取出、熱食與調味資料、一次食用扣除及營養結算。
- 三串批次耗 3 點油、3 次調料，取出 3 份且清空烤架。
- 油量／调料不足不前進、不扣料；刷油手部寫入失敗會回滾油與烤架，不播放成功音。
- 蘋果、胡蘿蔔、生牛肉的秘製串保留製作者、熟化為熟牛肉的食材快照、熱食與調味，結算營養 9。
- 普通烤串能按配置穿製，但不會被當成生串放入烤架。

已有測試另覆蓋拆串保留物品資料、完成／停止事件順序與遲到事件、剩餘空串、背包滿的出料、交易回滾、冷卻序列化及烤焦處置。這些來源測試不代表引擎收到玩家輸入或客戶端效果已通過。

| 流程段落 | 來源測試 | 原生 BDS | 真人客戶端 |

| 牛肉塊與雞皮自然取得 | 原包缺口已重現 | 公開註冊能力核對待本輪結果 | 未驗收，取得端仍阻塞 |
| 其他五個砧板擴充結果 | 原作者函式結果／數量通過 | 實際註冊核對待本輪結果 | 未驗收 |
| 19 固定串穿製至食用結算 | 連續函式測試通過 | 原生資料管線待本輪結果；不觸發玩家使用事件 | 未驗收 |
| 秘製串及普通串 | 已覆蓋資料與配置行為 | 秘製串原生資料管線待本輪結果 | 未驗收 |

魚串是目前較合適的真人起步驗收：釣得魚 → 木棍合成空串 → 副手空串／主手魚 → 穿製 → 準備油壺與基礎調料 → 點火 → 放串 → 刷油 → 空手四翻 → 撒料 → 取出 → 食用。仍須一起驗證磨粉、調料瓶配製／搖勻及油壺製備，不能用測試注入的油、瓶或生串當作生存流程成功。
