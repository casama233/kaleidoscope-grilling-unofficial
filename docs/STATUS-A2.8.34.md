# A2.8.34：餐盤資料與操作回滾

## 修正

- 放置、插入與取走烤串使用同一組有讀回確認的交易步驟。放置失敗會還原原方塊、原資料及來源；取串失敗會還原盤內資料與手持物品。
- 主手固定到操作開始時的實際欄位；副手固定到裝備欄位。回滾不跟隨玩家後來選中的欄位。
- 同時保留數量、名稱、RawMessage lore、可讀原生資料與自訂物品屬性。創造模式放置／插串不扣來源。
- 無法完整回滾時持久保存隔離標記，停止後續讀取與轉移，要求人工核對原始資料。
- 非字串、無效 JSON、超過五串、無效 ID、不支援的 native 版本或身份不一致不再被當成空盤。已移除方塊但仍殘留內容的座標不能直接覆寫。
- 補上餐盤四方向狀態與實際放置朝向。Java 1.1.1 的 `SkewerPlatePlacement` 使用玩家方向，沒有取反；模型旋轉對應原作的 SOUTH／WEST／NORTH／EAST。
- 指南更新版號，說明牛肉塊與雞皮需整套家族的 Board API。A2.8.31 已補來源接口，普通未擴充作者包仍無這條取得路徑。

## 驗證與限制

23 項交易回歸覆蓋主／副手、寫後拒絕、原方塊還原、完整物品資料、創造模式、殘留資料、隔離與方向邊界。它們使用儲存替身，不是 Minecraft 玩家或客戶端驗收。[獨立 BDS 證據](BDS-PLATE-TRANSACTIONS-20261002.json)已通過完整家族的原檔載入／重啟，以及另列 overlay 的原生方塊／容器／世界屬性、寫後故障回滾與重啟保留。兩次零錯誤、無實驗功能、零玩家。

交易是同步回滾，沒有宣稱程序突然終止時的跨儲存原子性。炸毀、支撐移除及打包掉落的完整持久交付仍需下一輪核對。餐盤烤串擺放、掛具內容與秘製串組合外觀的另一輪工作保留在其原有分支；本版未把它們寫成完成。

正式環境目前讀到 A2.8.31。本版不取代正式套件；完整家族逐檔收據及 static、bds、client、saved_world_migration 門檻仍適用。BDS 通過不代表真人渲染、吃東西動畫或既有正式存檔遷移通過。
