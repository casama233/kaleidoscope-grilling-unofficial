# Eating source contracts and remaining native checks

This source-only candidate builds on `20a7bce5f7d1ca8a520784695d7ede28594f2108`. Java's 25-tick checkpoint still commits one whole serving with full nutrition/effects; release grace remains one tick. The 90-tick native completion boundary remains start+89, zero remaining, exact identity, and completion/stop deduplication. No release identity was changed and no deployment was performed.

The reproduced defect is inconsistent projection admission. `grilled_gluten_skewer` has a native JSON duration of 100 ticks, so production selects THREE. Its serialized first-person projection is admitted only under THREE_ALT. The old server checked a flat item list and set `eat_projection=true`/played THREE, while the exact client item/profile gate rejected it. The new server checks the same generated item/profile table as the client. The regression fails against the original `20a7bce` production body with `true !== false`, then passes after the admission change. Unsupported native profiles retain the existing fallback and never assert that their Java projection is active.

All 41 explicitly profiled item JSONs were audited: 21 THREE_RANDOM items currently own a fixed 100-tick native duration. Of those, 19 appear in the old flat projection list and caused false admission; two were already excluded. The native duration chooses THREE at 100 and THREE_ALT at 90 without changing either ItemStack. Static JSON fixes the duration before `itemStartUse`; reproducing Java's random choice between 90 and 100 ticks remains unsupported by this implementation. Do not achieve it by replacing the item ID, rewriting metadata, or moving any inventory item.

The regression fixture previously ignored its `amount` parameter. It now creates the intended one-item fish serving, so the recorded early-release case actually checks an empty resulting hand. Additional tests cover terminal completion of the last fish serving without creating a helper stack, both hands, duplicate events, production elapsed-property snapshots consumed by real generated observer Molang, bite boundaries, and immediate stopped-use masking. These use API doubles and expression evaluation; they do not certify a remote Minecraft client.

The resolver is the pinned author's `SkewerEatingPiece.java`, commit `9a1acdab27698457bec16c9362678e574895a28c`, Git blob `447b3174972704be702233de60a41d38748515e1`, SHA256 `f89f3eb1dd742fa5ba79407ce11d5388c889599f4f211e0f0f9bec889b5676af`. Its namespace/raw-prefix/profile rule resolves the existing 47 piece asset files. Dynamic ingredient pieces use cloned ingredient snapshots in Java; admitting their native Bedrock renderer is a separate task. No guessed model mapping was added. [Pinned author source](https://github.com/breezeth-CN/KaleidoscopeGrilling/blob/9a1acdab27698457bec16c9362678e574895a28c/forge-1.20.1/src/main/java/cn/breezeth/kaleidoscope_grilling/skewer/SkewerEatingPiece.java).

The ONE source helper becomes scale 1 at 1.16667 seconds and stays scale 1 to completion. Its arm/socket/piece channels are constant from 2.75 seconds through 4.5 seconds, including both hands and the serialized rig expressions. These are now regression checked. Shrinking the helper late or moving it away from the camera would change the source and cannot be justified by the available evidence.

The two representative renderers still have two passes. The main and detached geometry roots are both named `grip`; the main root binds the current item slot, while the detached root binds the opposite slot. This is a concrete structural fact, not proof that native passes share a bone cache. Microsoft's query documentation specifies slot-to-bone mapping and equipped-slot queries, but provides no guarantee here about cross-pass cache behavior or updates of an empty helper slot. [Slot mapping](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/molangreference/examples/molangconcepts/queryfunctions/query_item_slot_to_bone_name?view=minecraft-bedrock-stable), [equipped-slot query](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/molangreference/examples/molangconcepts/queryfunctions/query_is_item_equipped?view=minecraft-bedrock-stable).

The separate `a03d89c6b8f27f93d34efa8c9dc635cf1d729d55` experiment combines ONE main/piece meshes into one render controller with a distinct `dual_grip` bound to the opposite slot. It preserves source curves, main vertices and texture pixels. It is excluded from this candidate, has no native acceptance, and its last full gate failed the older hand-anchor reference assertion. A single pass removes the duplicate root-name/pass arrangement as a controlled experiment; it does not prove that the native empty helper socket updates correctly.
